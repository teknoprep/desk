# Why things are the way they are

Design notes for every customization here, so a future agent does not "fix" something that is
deliberate. Each entry: what, where, why.

## `SUPER + mouse wheel` resizes kitty's font

`home/.config/hypr/bindings.lua` → `kitty_font_or_workspace()`

Kitty cannot bind the scroll wheel — its `mouse_map` has no scroll buttons and `map
super+scroll_up` is rejected ("Ignoring invalid mouse action"). So Hyprland catches the wheel and
forwards kitty's own shortcuts (`CTRL SHIFT + equal` / `minus`, down/up split in a 50 ms timer so
synthetic key state cannot stick). The bind checks the focused window's class: kitty → resize,
anything else → `focus m±1`, i.e. Omarchy's original wheel-workspace switch is preserved.

`ctrl+shift+equal`, `ctrl+shift+minus`, `ctrl+shift+backspace` (reset) still work from the keyboard.

## `deskstate`: desktop session snapshots

`home/.local/bin/deskstate*`, `home/.config/deskstate/README.md`, three user units,
`~/.config/omarchy/hooks/post-boot.d/deskstate-restore`, binding `SUPER + SHIFT + R`

A reboot or a power cut used to lose the layout: which windows were on which workspace/monitor,
kitty tabs with their cwds, the pi session behind each terminal, tmux panes and scrollback, and the
last ssh command per terminal. `deskstate` snapshots all of that every 60 s (plus once before a
clean shutdown, plus once at post-boot via the omarchy hook) and restores it on demand.

- `~/.local/state/deskstate/` holds runtime state and is **not** in this repo.
- The binding launches a terminal that runs `deskstate-restore-window`.
- `deskstate` reads kitty through its per-instance sockets, so kitty must have
  `~/.config/kitty/kitty.conf` (shipped here) for tabs to be recoverable.

## The two AI-generated themes

`home/.config/omarchy/themes/{machine-elf,elf-recursion}/`

Both were generated by an AI agent: `make-backgrounds.sh` / `make-backgrounds.py` in the theme
directory produce the 4K backgrounds, and `colors.toml` + `shell.toml` were derived from them.
The backgrounds are committed so the look survives without regenerating. Switch with
`omarchy theme set <name>`; the chosen background per theme is remembered by Omarchy.

## Superwhisper bar panel

`home/.config/omarchy/plugins/superwhisper-panel/`

Quickshell panel showing Superwhisper dictation state (idle / recording / transcribing), driven by
`status.py`, which reads Superwhisper's state. Font `SuperwhisperStatus.ttf` ships with it.
Requires `omarchy install dictation superwhisper`.

## Omarchy menu extra row

`home/.config/omarchy/extensions/omarchy-menu.jsonc` → `setup.displays`

Adds **Setup → Displays (drag & drop)** which launches `nwg-displays`. Omarchy's own
**Setup → Monitors** opens `monitors.lua` as text; both are kept because they serve different
purposes. Aliases (`disp`, `nwg`, `monitor layout`, …) make it findable by typing in the menu.

## Local LLMs are not tracked

The Ollama setup (`~/.pi/agent/models.json` and an `ollama.service.d` drop-in) is tuned to one GPU,
one VRAM budget and one model mix. Those numbers are wrong on any other machine, and installing them
would make a laptop behave badly. The local LLM stack is deliberately absent and `desk` never
touches `ollama`.

## The look lives in state, not in a config file

`desk` copying `home/` used to be enough for everything except the thing that is most
visible: which theme is on, which of that theme's backgrounds is showing, and which font is
active. Omarchy keeps those in runtime state:

| Truth | Where |
|---|---|
| active theme | `~/.local/state/omarchy/current/theme.name` |
| active background | the symlink `~/.local/state/omarchy/current/background` |
| per-theme background memory | `~/.local/state/omarchy/theme-backgrounds/<theme>` |
| active font | fontconfig (`omarchy font current`) |

A pull on another machine therefore got the theme *files* and then came up on whatever background
that machine had remembered — or on the stale one in `theme-backgrounds/` (this desk's own file
said `2-deeper-down.jpg` while `3-the-swarm.jpg` was on screen). `state/omarchy/` now records all
three, `desk` applies `theme set` → `bg set` → `font set` in that order, and it also rewrites
`theme-backgrounds/<theme>` so a later theme switch cannot resurrect the stale picture.
`scripts/verify.sh` compares all three against the live session.

`window-opaque.lua` is in the same category: it is user config that lives under `state/`, and
without it every window goes back to Omarchy's default transparency.

## GitHub credential helper

`git config --global credential."https://github.com".helper '!gh auth git-credential'`

`gh auth login` writes an absolute, version-pinned path to the helper when gh comes from mise
(`.../installs/gh/2.103.3/...`), which breaks the moment gh is upgraded. The `!gh …` form resolves
through `PATH`/mise instead. Re-running `gh auth setup-git` re-breaks it.

## Alacritty / foot / kitty

`kitty.conf` overrides Omarchy's defaults: tab bar along the top, and `mouse_hide_wait 0` so the
pointer never disappears over a terminal. The theming `include` line is Omarchy's — do not remove it
or the terminal stops following the theme.

## `mouse_hide_wait 0` and the cursor artefacts

The "red flicker / wrong cursor glyph on the side monitor" was the pointer being hidden and re-shown
at a different shape than the window under it expected. `mouse_hide_wait 0` keeps the pointer visible
so no stale glyph can be painted. Do not "tidy" this setting away.

## `~/.bashrc` — history written on every prompt

`histappend` (already set by Omarchy) plus `PROMPT_COMMAND="history -a…"` means the command is in
`~/.bash_history` the moment the prompt returns, not when the shell exits. That is what lets a
deskstate-restored terminal recall the last command (typically the `ssh host` before a dropped
session) with a single Up-arrow. Only these two lines are custom; everything above is Omarchy's.

## `vitals` is a separate repo, on purpose

The system monitor is a real application (Qt Quick + C++, PKGBUILD, tests), not a dotfile. Its
upstream is <https://github.com/teknoprep/vitals>. The kit vendors the source under `apps/vitals/` so
that `./desk install vitals` works from a clone with no second checkout; that copy is not edited here
except when syncing from upstream, and the desktop file and menu row live with the config.

## Only `settings.json` from Superwhisper

`~/.config/superwhisper/shortcuts.lua` and `hypr-block.lua` are generated by Superwhisper from
`settings.json`, and `hypr-block.lua` contains an absolute `dofile("~/.…")` path. Copying
them to a machine with a different username breaks Hyprland's config load. `settings.json` (vocabulary,
favourite models, mode keys, replacements) is the only hand-edited part, so that is what ships.


## Second sweep: apps, editor, and desktop state

Why these were missing the first time: the first pass was built from a `-newermt` scan of `~/.config`
plus the files an agent had been seen writing. That missed anything modified in place by a background
service (Superwhisper preferences, nwg-displays), anything installed before the scan window
(`~/.config/nvim`), and anything edited by hand (`wireplumber` KEF rule, `mimeapps.list`, web-app
launchers). The second sweep is a full `comm` of `~/.config` against the repo, so the default is now
"tracked unless it is a credential or runtime state", not "tracked if someone remembered".

Files that are byte-identical to `/usr/share/omarchy/config/*` are excluded on purpose:
`btop/btop.conf`, `starship.toml`, `tmux/tmux.conf`. Omarchy migrations rewrite them; a stale copy in
this repo would pin an old default.

`~/.config/nvim` is Omarchy's LazyVim install (`lazyvim.json` extra `editor.neo-tree`) plus local
plugins. `lazy-lock.json` is tracked so `:Lazy restore` reproduces exact plugin commits — do not treat
it as noise.

`kef-lsx-no-suspend.conf` exists because the KEF LSX II LT drops off USB after idle
(`usb_set_interface … -110`) and only a replug brings it back. `session.suspend-timeout-seconds = 0`
keeps the stream open. Removing this rule looks like a "cleanup" and re-breaks the speakers.

`~/.claude/themes/omarchy.json` and `~/.pi/agent/themes/omarchy-system.json` are the same palette
translated for two different agent CLIs — both are regenerated by hand when the theme changes.

## deskstate: workspace ids are not identity

Hyprland numbers workspaces globally; Omarchy gives each monitor a block of ten and renumbers
them when an output comes or goes (`default/hypr/monitor-workspaces.lua`, state in
`~/.local/state/omarchy/monitor-workspaces`). So a workspace id recorded yesterday can be another
monitor's workspace today, and windows end up "one desktop over" with nobody having asked.

The snapshot therefore stores three things per window: `slot` (which of the monitor's ten), the
connector, and `monitor_desc` (make/model/serial). `target_workspace()` resolves those against
Omarchy's live mapping. Never restore or move a window by a raw id from a snapshot.

`deskstate reconcile` fixes windows that are already out of place; `deskstate-watch.service` runs
it on the two structural events that cause drift (a monitor added/removed, two or more windows
relocating together). One window moving is always left alone — that is the user.

Two smaller findings from the same session, both fixed:

- The old 20 s wait for a non-browser window was simply too short on a cold boot with four
  outputs coming up. `vitals` was reported as "did not come back" and mapped seconds later. It is
  45 s now (60 s for browsers), with one retry through `uwsm-app --` and stderr captured to
  `restore-apps.log` instead of `/dev/null`.
- `hyprctl dispatch <classic-dispatcher>` does not exist on this build; dispatch arguments are Lua
  expressions. `hyprctl dispatch movetoworkspacesilent 11,address:0x…` only prints a parse error
  and does nothing. Use `hyprctl eval 'hl.dispatch(hl.dsp.window.move({ … }))'`, which is what
  deskstate does.

## Monitors are configured on the machine, never in this repo

Modes, positions, scale and rotation are a property of one desk's cables, not of a setup kit. This
repo carries no `hypr/monitors.lua`; `hyprland.lua` loads it only if it exists. Arrange displays with
the **Displays** app (`nwg-displays`, in the menu as Setup -> Displays), which writes that file for
the machine it runs on. The same rule applies to anything else that only makes sense for one exact
piece of hardware.

## Idle: 2 minutes of screensaver, 20 to lock, 10 more to a dark panel

`~/.config/omarchy/shell.json`:

```json
"idle": { "screensaver": 120, "lock": 1200, "blank": 600 }
```

Omarchy's idle service starts one cycle at the first of those deadlines (120 s), launches the
screensaver there, and locks `lock - screensaver` seconds later (1080 s). Dismissing the
screensaver before the lock deadline cancels the pending lock. `idle-settings` writes these three
numbers; the running shell watches the file, so no restart is needed.

### `blank` is a local patch, and the panels are dimmed, not DPMS'd

Two Omarchy behaviours had to be changed, both in
`/usr/share/omarchy/shell/plugins/lock/Service.qml`:

1. **The delay is hardcoded.** `idleBlankTimer.idleMs = 5000` — five seconds after the lock appears,
   regardless of what you want. `omarchy-patch-idle-blank` makes it read `idle.blank`.
2. **The blank does nothing on this build.** It calls `omarchy-brightness-display off`, whose whole
   body is `hyprctl dispatch 'hl.dsp.dpms({ action = "disable" })'`. On Hyprland 0.56.2 the
   dispatcher accepts that (returns `ok`) and **never changes `dpmsStatus`** — verified: all four
   outputs stayed `dpms=true`. So the screens stayed lit forever, which is why "screen goes black"
   never happened.

The patch sends blank/wake through `~/.local/bin/screen-power`, which sets **DDC/CI brightness to 0**
on every monitor that answers on VCP 0x10 (the script lists them with `screen-power status`) and restores the exact levels afterwards. The panels go fully dark and any key wakes them
instantly, because the panel never leaves the compositor.

The alternative — real DPMS — would mean disabling the outputs (`monitor = DP,disable`), which
reflows workspaces and fights the per-monitor blocks. Not worth it for the same visual result.

If Hyprland fixes `hl.dsp.dpms`, delete the `screen-power` wiring and the brightness step becomes
unnecessary; the `idle.blank` half of the patch is still wanted.

### Never suspend, except a lid

`logind`'s `IdleAction` was already `ignore` by default; `/etc/systemd/logind.conf.d/50-no-idle-sleep.conf`
pins it so an update or a config change cannot start suspending the desktop, and sets
`HandleLidSwitch=suspend` (docked: ignore) for a laptop. Manual suspend, the power menu and
`systemctl suspend` keep working — this only removes *idle* suspend.

`omarchy update` replaces `/usr/share/omarchy`, so
`~/.config/omarchy/hooks/post-update.d/90-idle-blank-patch` re-applies the patch and restarts the
shell, with a notification either way.

## Super+F fullscreen survives a restore

Hyprland's per-client `fullscreen` is 0 none, 1 maximized, 2 fullscreen, 3 both; Super+F sets 2.
deskstate used to "clear" fullscreen by toggling `mode = "maximized"` up to three times, which never
touches fullscreen and can leave a fullscreen window as fullscreen+maximized (3). `place()` and
`reconcile` now call `set_fullscreen()`, which sets each mode explicitly:

```lua
hl.dsp.window.fullscreen({ window = "address:0x…", mode = "fullscreen", action = "set" })
hl.dsp.window.fullscreen({ window = "address:0x…", mode = "maximized",  action = "unset" })
```

`action = "set"/"unset"` is idempotent, so it can be applied to a window that is already correct —
which is what makes it safe in `reconcile`. Reconcile also re-applies the recorded state after a
move, because moving a window can drop fullscreen.

## Two workspace guards exist right now

`~/.config/hypr/window-pin.lua` (a Hyprland config module, loaded from `hyprland.lua`) and
deskstate's `watch`/`reconcile` solve the same problem from opposite ends: window-pin reacts inside
the compositor on display changes, deskstate corrects from the outside on monitor events and grouped
moves. They do not currently conflict — window-pin restores on display change within 12 s, deskstate
answers the same events 6 s later and finds nothing to do — but keeping both is duplication. Pick one
when one of them proves itself; do not let them drift into fighting (e.g. do not raise deskstate's
patience above window-pin's settle window without reconsidering).
